# Shelf HTTP API v1

This document is the authoritative contract for Shelf's HTTP API as currently implemented.

## Quick start

The API server is disabled by default. Open **Settings → API server**, enable it, and save the settings. The defaults are:

```text
Interface: localhost
Port:      9876
Base URL:  http://localhost:9876/api/v1
```

The bind interface and port are configurable. The preference is kept in `api-server-preference.json` in Shelf's application-local-data directory and is applied at startup.

For the examples below:

```sh
BASE='http://localhost:9876/api/v1'
ID='11111111-1111-4111-8111-111111111111'
COLLECTION_ID='22222222-2222-4222-8222-222222222222'
```

All JSON request bodies require this header:

```sh
-H 'content-type: application/json'
```

## Security and transport

- The API is opt-in but has no API key, token, or other authentication.
- Traffic is plain HTTP; TLS is not provided by Shelf.
- Browser CORS is not enabled.
- Keep the interface set to `localhost` unless every user and device able to reach the bound interface is trusted.
- The app lock protects library operations, which return `423 Locked` while Shelf is locked.
- Discovery, health, security status, lock, and unlock remain reachable while locked.
- Unlock passwords sent to a non-local listener travel over plain HTTP.
- Storage, import, and export paths refer to the filesystem of the computer running Shelf, not the caller's filesystem.

## Conventions

- Request and response property names use `camelCase`.
- Timestamps are RFC 3339 UTC strings, for example `2026-08-14T10:30:00+00:00`.
- Bookmark and collection IDs are UUID strings generated by Shelf unless retained from an imported CSV.
- Optional response properties are serialized as `null`, not omitted.
- Successful endpoints currently return HTTP `200 OK`.
- Mutations return the complete current `AppSnapshot` unless a more specific response is documented.
- Bookmark listing uses zero-based offset pagination. `offset` defaults to `0`; `limit` defaults to `100` and may not exceed `1,000`.
- `POST /bookmarks` ignores a supplied `id`; `PUT /bookmarks/:id` uses the path ID.
- `POST /collections` ignores a supplied `id`; `PUT /collections/:id` uses the path ID.
- Bookmark URLs are normalized to HTTP/HTTPS URLs and fragments are removed.

## Common schemas

### `BookmarkDraft`

Used by bookmark create and replace requests.

| Property | Type | Required | Default/behavior |
| --- | --- | --- | --- |
| `id` | string or null | No | Ignored by HTTP create/replace routing. |
| `url` | string | Yes | Normalized; only HTTP and HTTPS are accepted. |
| `title` | string or null | No | URL domain when absent or blank. |
| `description` | string or null | No | Empty text becomes `null`. |
| `imageUrl` | string or null | No | Page image URL. |
| `faviconUrl` | string or null | No | Favicon URL. |
| `siteName` | string or null | No | Site/publisher name. |
| `author` | string or null | No | Page author. |
| `publishedAt` | string or null | No | Source publication value. |
| `tags` | string[] | No | `[]`; normalized and deduplicated. |
| `collectionId` | string or null | No | Unknown collection IDs become `null`. |
| `favorite` | boolean | No | `false`. |
| `archived` | boolean | No | `false`. |
| `notes` | string or null | No | Empty text becomes `null`. |
| `archiveMode` | `"none"` or `"html"` | No | `"none"`. Setting `html` queues and starts saved-copy capture. |

Bookmark creation accepts these additional API-only properties alongside the draft fields. They are supported by both single and batch creation, and are not stored on the bookmark:

| Property | Type | Required | Default/behavior |
| --- | --- | --- | --- |
| `fetchMetadata` | boolean | No | `false`. When true, extract page metadata before inserting the bookmark. Redirect resolution still occurs when false. |
| `metadataBehavior` | `"add-new-only"` or `"override"` | No | `"add-new-only"`. Only used when `fetchMetadata` is true. |

Metadata behavior applies to `title`, `description`, `imageUrl`, `faviconUrl`, `siteName`, `author`, and `publishedAt`:

- `add-new-only` preserves every caller-supplied, non-blank metadata value and fills only missing or blank values from the fetched page.
- `override` replaces all metadata fields with fetched values, including replacing a supplied value with `null` when the page does not provide that field.
- In both modes, successful metadata fetching uses the final URL after redirects. Tags, collection, favorite/archive state, notes, and saved-copy mode always remain caller-controlled.

## Bookmarks

### `GET /api/v1/bookmarks`

Lists bookmarks, including archived bookmarks, using zero-based offset pagination.

Shelf's desktop filter row is evaluated locally against its current snapshot; these controls are not additional query properties on this endpoint. API clients can reproduce the same filters from `Bookmark` fields:

| Desktop filter | Bookmark data and behavior |
| --- | --- |
| Date added | Compare the local calendar date derived from `createdAt` with an inclusive From/To range. Either boundary may be omitted. |
| Domain | Match `domain` against any selected domain. The desktop multi-select is searchable; multiple selections use OR. |
| Has saved copy | Require `archive.htmlAvailable` to be `true`. |
| Favorite | Require `favorite` to be `true`. |
| Never opened | Require `openCount` to be `0` and `lastOpenedAt` to be `null`. |
| Has notes | Require non-empty `notes`. |
| No tags | Require an empty `tags` array. |

The active desktop criteria are combined with AND. Use `GET /api/v1/snapshot` when a complete client-side filter pass is needed, or paginate through this endpoint before filtering.

| Query property | Type | Required | Default/behavior |
| --- | --- | --- | --- |
| `offset` | non-negative integer | No | `0`; the number of bookmarks to skip. An offset at or beyond `total` returns an empty `bookmarks` array. |
| `limit` | positive integer | No | `100`; must be between `1` and `1,000`, inclusive. |

```sh
curl "$BASE/bookmarks?offset=0&limit=100"
```

Response `200`:

```json
{
  "bookmarks": [
    {
      "id": "11111111-1111-4111-8111-111111111111",
      "url": "https://example.com/article",
      "title": "Example article",
      "description": null,
      "imageUrl": null,
      "faviconUrl": null,
      "siteName": null,
      "author": null,
      "publishedAt": null,
      "domain": "example.com",
      "tags": ["reading"],
      "collectionId": null,
      "favorite": false,
      "archived": false,
      "notes": null,
      "createdAt": "2026-08-14T10:30:00+00:00",
      "updatedAt": "2026-08-14T10:30:00+00:00",
      "lastOpenedAt": null,
      "openCount": 0,
      "archive": {
        "mode": "none",
        "folder": null,
        "updatedAt": null,
        "htmlAvailable": false,
        "textAvailable": false
      }
    }
  ],
  "offset": 0,
  "limit": 100,
  "total": 6910
}
```

`total` is the complete bookmark count at the time of the request, independent of `offset` and `limit`. To retrieve the next page, add `limit` to `offset` and continue while the new offset is less than `total`. If bookmarks are added or removed between page requests, later offset-based pages can shift; restart pagination when a consistent traversal is required.

Errors: `400` for a malformed `offset`/`limit` or a `limit` outside `1`–`1,000`; `423` while locked.

### `POST /api/v1/bookmarks`

Creates a bookmark. Shelf resolves redirects before duplicate detection and persistence; if URL resolution cannot reach the page, it keeps the normalized input URL. If `archiveMode` is `html`, Shelf queues and starts saved-copy capture in the background. Page metadata is not extracted unless `fetchMetadata` is true.

```sh
curl -X POST "$BASE/bookmarks" \
  -H 'content-type: application/json' \
  -d '{
    "url": "https://example.com/article#introduction",
    "title": "Example article",
    "tags": ["Reading", "example"],
    "collectionId": "22222222-2222-4222-8222-222222222222",
    "favorite": true,
    "fetchMetadata": true,
    "metadataBehavior": "add-new-only",
    "archiveMode": "none"
  }'
```

Response `200`: the resulting [`AppSnapshot`](#appsnapshot), including the created bookmark with a generated ID and normalized URL.

Errors: `400` for invalid/unsupported input, `409` for a duplicate URL, `423` while locked, or `502` when requested metadata cannot be fetched. A locked request is rejected before metadata is fetched.

### `POST /api/v1/bookmarks/batch`

Creates between 1 and 1,000 bookmarks in one call. Each item accepts the complete `BookmarkDraft` shape plus its own `fetchMetadata` and `metadataBehavior` settings.

```sh
curl -X POST "$BASE/bookmarks/batch" \
  -H 'content-type: application/json' \
  -d '{
    "bookmarks": [
      {
        "url": "https://example.com/with-known-title",
        "title": "Title supplied by the caller",
        "fetchMetadata": true,
        "metadataBehavior": "add-new-only",
        "tags": ["imported"]
      },
      {
        "url": "https://example.org/fetch-everything",
        "fetchMetadata": true,
        "metadataBehavior": "override"
      },
      {
        "url": "https://example.net/without-metadata",
        "title": "Already complete",
        "fetchMetadata": false
      }
    ]
  }'
```

Response `200`: the resulting [`AppSnapshot`](#appsnapshot), including every inserted bookmark. IDs supplied by items are ignored and Shelf generates new IDs.

The insert is atomic: Shelf normalizes every URL, resolves redirects with bounded concurrency, rejects duplicate destination URLs against the existing library or within the batch, and persists the bookmarks once. If URL resolution is unavailable, Shelf retains the normalized input URL. If validation or any requested metadata fetch fails, no bookmarks from the batch are inserted. Saved-copy jobs requested with `archiveMode: "html"` are queued after the bookmark data is persisted and processed in the background.

Errors: `400` for an empty batch, more than 1,000 items, invalid input, or malformed page metadata; `409` when any normalized/final URL already exists or occurs more than once in the batch; `423` while locked; or `502` when any requested metadata fetch fails. Error messages identify the one-based bookmark position when applicable.

### `GET /api/v1/bookmarks/:id`

Returns one bookmark.

```sh
curl "$BASE/bookmarks/$ID"
```

Response `200`: one [`Bookmark`](#bookmark), as shown in the common schema example.

Errors: `404` if the ID does not exist or `423` while locked.

### `PUT /api/v1/bookmarks/:id`

Replaces all editable fields using `BookmarkDraft`. Omitted defaulted fields become their defaults, so callers should send the complete desired editable state. The path ID overrides any body `id`.

```sh
curl -X PUT "$BASE/bookmarks/$ID" \
  -H 'content-type: application/json' \
  -d '{
    "url": "https://example.com/article",
    "title": "Updated example article",
    "description": "Updated description",
    "tags": ["reading", "updated"],
    "collectionId": null,
    "favorite": true,
    "archived": false,
    "notes": "Review later",
    "archiveMode": "html"
  }'
```

Response `200`: the resulting [`AppSnapshot`](#appsnapshot). An HTML mode queues and starts background capture.

Errors: `400` for invalid input, `404` if the bookmark is missing, `409` if its URL duplicates another bookmark, or `423` while locked.

### `DELETE /api/v1/bookmarks/:id`

Deletes the bookmark, its pending archive work, and any saved-copy folder.

```sh
curl -X DELETE "$BASE/bookmarks/$ID"
```

Response `200`: the resulting [`AppSnapshot`](#appsnapshot), without the deleted bookmark.

Errors: `404` if missing or `423` while locked.

### `PATCH /api/v1/bookmarks/:id/status`

Updates either or both status flags. Omitted flags remain unchanged.

```sh
curl -X PATCH "$BASE/bookmarks/$ID/status" \
  -H 'content-type: application/json' \
  -d '{
    "favorite": true,
    "archived": false
  }'
```

Request shape:

```json
{
  "favorite": true,
  "archived": false
}
```

Response `200`: the resulting [`AppSnapshot`](#appsnapshot).

Errors: `404` if missing or `423` while locked.

### `POST /api/v1/bookmarks/:id/opened`

Increments `openCount` and sets `lastOpenedAt`. It records a visit but does not open a browser on the API client's behalf.

```sh
curl -X POST "$BASE/bookmarks/$ID/opened"
```

Response `200`: the resulting [`AppSnapshot`](#appsnapshot), with the new visit count and timestamp.

Errors: `404` if missing or `423` while locked.

Fetches and parses metadata without changing the library.

```sh
curl -X POST "$BASE/metadata" \
  -H 'content-type: application/json' \
```

Request:

```json
{
  "url": "https://example.com/article"
}
```

```json
{
  "url": "https://example.com/article",
  "title": "Example article",
  "description": "A useful example page.",
  "imageUrl": "https://example.com/cover.jpg",
  "faviconUrl": "https://example.com/favicon.ico",
  "siteName": "Example",
  "author": "A. Writer",
  "publishedAt": "2026-08-01",
  "domain": "example.com"
}
```

### `POST /api/v1/bookmarks/:id/metadata`

Fetches the stored URL and replaces the bookmark's URL, title, description, image, favicon, site name, author, publication value, and domain. Tags, collection, flags, and notes remain intact. The operation aborts if the bookmark changes while the request is in flight.

```sh
curl -X POST "$BASE/bookmarks/$ID/metadata"
```

Response `200`: the resulting [`AppSnapshot`](#appsnapshot), containing refreshed metadata.

Errors: `400` for invalid or concurrently changed data or a page larger than the configured maximum page-size limit (10 MB by default, adjustable in the app's Miscellaneous settings), `404` if missing, `409` if the final URL duplicates another bookmark, `423` while locked, or `502` for mapped fetch failures.

## Saved copies and archive search

### Enabling versus refreshing saved copies

Set `archiveMode: "html"` through bookmark creation or replacement to enable and queue a saved copy. `PUT /bookmarks/:id/archive` captures or refreshes the requested mode for a bookmark whose configured archive mode matches it. Use `DELETE /bookmarks/:id/archive` to remove and disable the copy.

### `PUT /api/v1/bookmarks/:id/archive`

Captures or refreshes saved HTML. A JSON body is required; `mode` defaults to `html` when omitted.

```sh
curl -X PUT "$BASE/bookmarks/$ID/archive" \
  -H 'content-type: application/json' \
  -d '{"mode":"html"}'
```

Request:

```json
{
  "mode": "html"
}
```

Response `200`: the resulting [`AppSnapshot`](#appsnapshot), with archive availability and timestamps updated after capture.

Errors: `400` for capture/filesystem/page failures, `404` if missing, `423` while locked, or `502` for mapped fetch failures.

### `DELETE /api/v1/bookmarks/:id/archive`

Removes the saved-copy folder, clears its pending work, and resets archive mode to `none`.

```sh
curl -X DELETE "$BASE/bookmarks/$ID/archive"
```

Response `200`: the resulting [`AppSnapshot`](#appsnapshot), with default archive information.

Errors: `404` if missing or `423` while locked; filesystem failures return `400`.

### `GET /api/v1/bookmarks/:id/archive/html`

Returns saved HTML and the final captured URL used as its render base.

```sh
curl "$BASE/bookmarks/$ID/archive/html"
```

Response `200`:

```json
{
  "html": "<!doctype html><html><head><title>Example</title></head><body>Saved page</body></html>",
  "baseUrl": "https://example.com/article"
}
```

Errors: `400` when the bookmark has no configured saved copy, `404` when the bookmark is missing or its configured copy is unavailable, or `423` while locked.

### `POST /api/v1/bookmarks/:id/archive/export`

Writes the saved raw HTML to an absolute or otherwise host-resolvable file path. Existing target-file behavior follows the host filesystem's normal create/write semantics.

```sh
curl -X POST "$BASE/bookmarks/$ID/archive/export" \
  -H 'content-type: application/json' \
  -d '{"path":"/Users/example/Exports/example-article.html"}'
```

Request:

```json
{
  "path": "/Users/example/Exports/example-article.html"
}
```

Response `200`:

```json
{
  "exported": true
}
```

Errors: `400` when no copy is configured or for host filesystem failures, `404` when the bookmark is missing or its configured copy is unavailable, or `423` while locked.

### `GET /api/v1/archives/search?q=...`

Searches extracted saved-copy text with exact, prefix, typo-tolerant, and subsequence scoring. An absent or blank `q` returns an empty array.

```sh
curl --get "$BASE/archives/search" --data-urlencode 'q=rust archive'
```

Response `200`:

```json
[
  {
    "id": "11111111-1111-4111-8111-111111111111",
    "score": 18.5
  }
]
```

Errors: `423` while locked; archive read failures may return `400`.

### `POST /api/v1/archives/process-pending`

Processes each currently queued archive job at most once during the request. Individual retryable capture failures remain queued. If a worker is already active, this returns the current snapshot.

```sh
curl -X POST "$BASE/archives/process-pending"
```

Response `200`: the resulting [`AppSnapshot`](#appsnapshot), including any jobs still pending.

Errors: `423` while locked or `400` for queue/state failures. Individual page-capture failures are logged and left queued rather than failing the whole request.

## Saved queries

Saved queries store search text only. Selecting one in the desktop app reruns the existing search against the latest bookmark metadata and saved-page text; no bookmark membership or cached result IDs are stored.

### `GET /api/v1/saved-queries`

Lists saved queries in creation order.

```sh
curl "$BASE/saved-queries"
```

Response `200`: an array of [`SavedQuery`](#savedquery) objects. Errors: `423` while locked.

### `POST /api/v1/saved-queries`

Creates a saved query. Names are unique without regard to case. Query text is validated for supported Boolean operators, non-empty terms, and balanced parentheses.

```sh
curl -X POST "$BASE/saved-queries" \
  -H 'content-type: application/json' \
  -d '{"name":"Rust tutorials","query":"#rust AND tutorial -video"}'
```

Response `200`: the resulting [`AppSnapshot`](#appsnapshot). Errors: `400` for invalid input, `409` for a duplicate name, or `423` while locked.

### `PUT /api/v1/saved-queries/:id`

Replaces the saved query's name and query text. The path ID is authoritative.

```sh
curl -X PUT "$BASE/saved-queries/$SAVED_QUERY_ID" \
  -H 'content-type: application/json' \
  -d '{"name":"Rust learning","query":"#rust AND (tutorial OR guide) -video"}'
```

Response `200`: the resulting [`AppSnapshot`](#appsnapshot). Errors: `400` for invalid input, `404` if missing, `409` for a duplicate name, or `423` while locked.

### `DELETE /api/v1/saved-queries/:id`

Deletes the saved query without changing any bookmarks.

```sh
curl -X DELETE "$BASE/saved-queries/$SAVED_QUERY_ID"
```

Response `200`: the resulting [`AppSnapshot`](#appsnapshot). Errors: `404` if missing or `423` while locked.

## App lock

### `GET /api/v1/security`

Returns app-lock status and is available while locked.

```sh
curl "$BASE/security"
```

Response `200`:

```json
{
  "passwordConfigured": true,
  "timeoutMinutes": 15,
  "locked": false
}
```

### `PUT /api/v1/security`

Enables, updates, or removes the password. `timeoutMinutes` is required and must be from 1 through 1,440. Passwords must contain 8 through 1,024 Unicode characters.

Enable the lock when no password exists:

```sh
curl -X PUT "$BASE/security" \
  -H 'content-type: application/json' \
  -d '{
    "newPassword": "correct horse battery staple",
    "timeoutMinutes": 15,
    "removePassword": false
  }'
```

Change the password and timeout:

```sh
curl -X PUT "$BASE/security" \
  -H 'content-type: application/json' \
  -d '{
    "currentPassword": "correct horse battery staple",
    "newPassword": "a different strong password",
    "timeoutMinutes": 30,
    "removePassword": false
  }'
```

Keep the password but change only the timeout by omitting `newPassword`. Remove the app lock with `removePassword: true` and the current password:

```sh
curl -X PUT "$BASE/security" \
  -H 'content-type: application/json' \
  -d '{
    "currentPassword": "a different strong password",
    "timeoutMinutes": 30,
    "removePassword": true
  }'
```

Request shape:

```json
{
  "currentPassword": "existing password or null",
  "newPassword": "new password or null",
  "timeoutMinutes": 15,
  "removePassword": false
}
```

Response `200`:

```json
{
  "passwordConfigured": true,
  "timeoutMinutes": 15,
  "locked": false
}
```

Errors: `400` for invalid timeout/password/current credentials or an invalid removal request; `423` if an existing configured lock is currently locked.

### `POST /api/v1/security/lock`

Locks Shelf immediately when a password is configured. With no password, it remains unlocked.

```sh
curl -X POST "$BASE/security/lock"
```

Response `200`:

```json
{
  "passwordConfigured": true,
  "timeoutMinutes": 15,
  "locked": true
}
```

### `POST /api/v1/security/unlock`

Unlocks Shelf. If no password is configured, it simply returns the current snapshot.

```sh
curl -X POST "$BASE/security/unlock" \
  -H 'content-type: application/json' \
  -d '{"password":"correct horse battery staple"}'
```

Request:

```json
{
  "password": "correct horse battery staple"
}
```

Response `200`: the current [`AppSnapshot`](#appsnapshot).

Errors: `400` for an incorrect password or invalid stored password settings.

## Storage and CSV

These endpoints operate on paths on the Shelf host. They expose the same capabilities as native dialogs but do not open dialogs themselves.

### `PUT /api/v1/storage`

Copies the current SQLite library and archive folders to a new location, makes that database active, and persists the preference. The directory must be absolute. A `.sqlite3` extension is added when absent. Portable-invalid names and collisions with Shelf preference files are rejected.

```sh
curl -X PUT "$BASE/storage" \
  -H 'content-type: application/json' \
  -d '{
    "directory": "/Users/example/Documents/Shelf",
    "fileName": "bookmarks.sqlite3",
    "overwrite": false
  }'
```

Request:

```json
{
  "directory": "/Users/example/Documents/Shelf",
  "fileName": "bookmarks.sqlite3",
  "overwrite": false
}
```

Response `200`: the resulting [`AppSnapshot`](#appsnapshot), with updated data and archive paths.

Errors: `400` for invalid paths/names or copy/write failures, `409` if the target exists and `overwrite` is false, or `423` while locked.

### `POST /api/v1/import/csv`

Imports a native/Shelf CSV file from the host. A URL column is required; accepted aliases include `url`, `link`, and `uri`. Other aliases include title/name, description/summary, collection/folder/group, tags/labels/keywords, and favorite/favourite/starred. The file is fully parsed and validated before mutation; rows with invalid URLs, timestamps, booleans, or visit counts are skipped. Repeated normalized URLs are merged (including the union of their tags) before existing Shelf bookmarks are updated, and missing collections are created. Raindrop.io source selection is currently available through the desktop Settings UI rather than this endpoint.

```sh
curl -X POST "$BASE/import/csv" \
  -H 'content-type: application/json' \
  -d '{"path":"/Users/example/Imports/bookmarks.csv"}'
```

Request:

```json
{
  "path": "/Users/example/Imports/bookmarks.csv"
}
```

Response `200`:

```json
{
  "imported": 12,
  "updated": 3,
  "skipped": 1
}
```

Errors: `400` for file/CSV parsing failures or `423` while locked.

### `POST /api/v1/export/csv`

Exports all bookmarks to a CSV file on the host. Collection IDs are represented by collection names and tags are joined with `|`.

```sh
curl -X POST "$BASE/export/csv" \
  -H 'content-type: application/json' \
  -d '{"path":"/Users/example/Exports/shelf-bookmarks.csv"}'
```

Request:

```json
{
  "path": "/Users/example/Exports/shelf-bookmarks.csv"
}
```

Response `200`:

```json
{
  "exported": 42
}
```

Errors: `400` for host file/write/CSV failures or `423` while locked.

## Error format and status codes

Application errors returned through Shelf's handlers use this JSON shape:

```json
{
  "error": "That bookmark no longer exists"
}
```

| Status | Meaning in Shelf |
| --- | --- |
| `200 OK` | Request completed successfully. |
| `400 Bad Request` | Application validation, credentials, URL, storage, CSV, archive, or general operation failure; also malformed JSON syntax from Axum. |
| `404 Not Found` | A requested bookmark, collection, saved query, or saved copy is missing, or the route itself does not exist. Known-resource errors use Shelf's JSON error shape. |
| `409 Conflict` | Duplicate bookmark URL, duplicate collection name, or existing storage target without overwrite approval. |
| `413 Payload Too Large` | Request body exceeded the HTTP framework's configured/default body limit. |
| `415 Unsupported Media Type` | A JSON endpoint received a body without an `application/json` content type. |
| `422 Unprocessable Entity` | JSON syntax was valid but required properties/types did not match the request schema. |
| `423 Locked` | The operation attempted to access protected library data while Shelf was locked. |
| `502 Bad Gateway` | A mapped remote page fetch or timeout failure occurred. |

Framework-generated routing, method, query, or JSON-extraction failures may be plain-text responses rather than Shelf's JSON error object. An unsupported HTTP method normally returns `405 Method Not Allowed`.

Representative errors:

```http
HTTP/1.1 423 Locked
content-type: application/json

{"error":"Shelf is locked"}
```

```http
HTTP/1.1 409 Conflict
content-type: application/json

{"error":"That URL is already on your Shelf"}
```

```http
HTTP/1.1 404 Not Found
content-type: application/json

{"error":"That bookmark no longer exists"}
```

```http
HTTP/1.1 400 Bad Request
content-type: application/json

{"error":"Only http and https URLs are supported"}
```

## Operational notes

- API server enablement/interface/port are configured in the desktop Settings UI, not through an HTTP endpoint.
- Reconfiguring the listener stops the old listener, attempts the new bind, and restores the previous listener if the new bind or preference write fails.
- A successful bookmark write with `archiveMode: "html"` returns before background capture necessarily finishes; inspect `pendingArchives` or the bookmark's `archive` object.
- Snapshot archive availability is derived from files on disk, so it reflects whether `page.html` and `content.txt` actually exist.
- Archive capture and metadata fetch contact remote URLs from the computer running Shelf.
- Import/export and storage APIs can read or write host paths reachable by Shelf's process permissions; expose the listener accordingly.
